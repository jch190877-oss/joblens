# 评价维度权重的确定方法（AHP）

这里放的是「5 个评价维度的权重从哪来」的可复现工具。目标是把权重从「我们觉得应该这样」变成「两位招聘者两两比较后算出来的，且一致性可检验」。

## 目录

| 文件 | 用途 |
| --- | --- |
| `问卷.html` | 给 HR 填写的两两比较问卷。浏览器打开即可，实时算权重和 CR，可打印、可导出 JSON |
| `ahp.py` | 读取导出的 JSON，输出每位专家的权重与 CR，以及多人合并后的最终权重 |

## 五个维度

| 维度 | 含义 | 产品里怎么算 |
| --- | --- | --- |
| 门槛达成 | 学历 / 专业 / 语言等硬性条件是否满足 | 硬性条件组内加权达成度 |
| 相关经历 | 核心职责是否有对应经历与证据 | 核心职责组内加权达成度 |
| 加分储备 | 加分项是否具备 | 加分项组内加权达成度 |
| 表达与结构 | 信息是否清晰、重点是否前置 | 投递前检查扣分（必须补 −20 / 注意 −8） |
| 可信度 | 是否存在无法核实或被夸大的信息 | 改写事实标记扣分（拦截 −12 / 待补数字 −6） |

## 操作步骤

1. 约 1–2 位 HR，每人 5 分钟，打开 `问卷.html` 填 10 次两两比较。
2. 填完点「计算权重」，看 CR：
   - **CR < 0.1** → 判断自洽，可以导出
   - **CR ≥ 0.1** → 判断存在矛盾（比如 A>B、B>C，却又说 C>A），请对方回看并调整
3. 点「导出 JSON」，把 `hr01.json`、`hr02.json` 放到本目录。
4. 运行：

```bash
python ahp.py hr01.json hr02.json
```

输出：

- 每位专家各自的权重、λmax、CI、CR
- 多人合并后的权重（判断矩阵取**几何平均**，再求一次特征向量）
- 一段可直接粘进源码的 TypeScript 常量

5. 验证脚本本身是否正常：

```bash
python ahp.py --self-test
```

会用一个「已知权重为 0.5/0.3/0.2 的完全一致矩阵」反推，检验特征向量算法。

## 为什么用几何平均合并

AHP 的判断是**比值**尺度（"重要 3 倍"），不是线性量，所以多位专家合并时用几何平均而不是算术平均；也避免了某一位专家给极端值时被平均掉。

## 为什么最终仍要人工确认

AHP 给出的是一组**可复核**的权重，不是客观真理。两位专家的判断如果出现分歧（比如一位认为门槛最重要、另一位认为经历最重要），应该：

1. 保留两组权重各自报告，说明分歧
2. 或请第三方裁决后再合并

这和产品里对待「经历类型有没有高低」那处分歧的做法一致——**不把分歧藏起来**。
